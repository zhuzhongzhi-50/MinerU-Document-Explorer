QMD 提问接口对外集成方案
（基于 /api/ask 的服务器侧问答 API）

1. 背景与目标

将「基于服务器知识库的问答能力」从网页前端抽离为一个独立的 HTTP 接口，供其他业务系统、脚本或第三方应用直接调用。

  • 全程在服务器端完成：检索服务器上的知识库集合 + 调用服务器配置的 LLM 生成答案。
  • 调用方只传问题，无需关心 embedding、检索、重排、模型推理等细节，也不持有 LLM 的 key。
  • 返回标准 JSON（非流式），便于程序解析与系统集成。

与网页聊天的区别：网页前端使用 /api/query（SSE 流式、逐字推送）；对外接口使用 /api/ask（一次性 JSON）。两者复用同一套服务端检索 + RAG 流水线，能力一致。

2. 整体架构

调用方系统  ──POST /api/ask(JSON)──>  QMD 服务端  ──>  ①查询扩展 → ②混合检索(BM25+向量，命中服务器集合) → ③重排 → ④LLM 生成(服务器 llmBaseUrl/apiKey/model)
                                              │
                                              └──>  返回 JSON { answer, sources, model, ... }

知识库与 LLM 均在服务端，调用方无感。实现位置：src/api/server.ts 中的 POST /api/ask 处理函数。

3. 接口规范

3.1 基本信息

项值
路径POST /api/ask
请求头Content-Type: application/json；Authorization: Bearer <token>
响应格式application/json（非流式，单次返回）
鉴权需要合法 Bearer Token（详见第 4 节）

3.2 请求体（JSON）

字段类型必填说明
querystring是用户问题。缺失或为空返回 400。
collectionsstring[]否指定检索的知识库集合，如 ["ceshi"]。不填则走服务器默认集合。
collectionstring否单个集合的简写，等价于 collections:[collection]。
limitnumber否检索候选条数，默认取服务端配置。
minScorenumber否最低相关分阈值。
topKnumber否送入 LLM 的上下文条数。
intentstring否检索意图提示（如 "default"）。

3.3 响应体（JSON）

字段类型说明
querystring回显的问题。
modelstring实际使用的 LLM 模型名（服务器侧配置）。
answerstring生成的答案文本。
errorstring|null生成阶段错误（如 LLM 不可达）；为空表示成功。
sourcesarray引用的知识库片段（标题、文件、分数等）。
rawResultsarray检索原始结果（文件、分数、chunk 文本）。

3.4 错误码

  • 400：请求体非法（JSON 解析失败 / 缺少 query）。
  • 401：未提供或 Token 无效。
  • 500：检索阶段失败，响应体含 { "error": "检索失败: ..." }。
  • 生成阶段失败：仍返回 200，但 error 字段非空（如 问答请求失败: fetch failed，多为 LLM 地址不可达）。

4. 认证方案

4.1 现状（快速可用）

复用现有 Bearer Token 体系：任意合法 token 即可调用 /api/ask。登录获取 token：POST /api/auth/login。

4.2 推荐（正式对外前）

新增只读「查询 Token」作用域：

  • 仅允许访问 POST /api/ask 及可选的 GET /api/collections；
  • 访问其它路由（如 PUT /api/config、/api/users）一律返回 403；
  • 通过环境变量（如 QMD_QUERY_TOKEN）下发，可分发给多个外部系统。

不要用 QMD_ALLOW_ANONYMOUS=true 来暴露接口——该开关会让所有 /api 路由匿名开放，包括配置写入与用户管理，存在严重安全风险。

4.3 纵深防御

在服务器安全组 / 防火墙将 8787 端口仅放行调用方 IP，避免接口被公网任意扫描调用。

5. 知识库范围

  • 默认检索服务器配置的默认集合（defaultCollections）；
  • 调用方可经 collections 字段指定，例如 {"collections":["ceshi"]}；
  • 建议在服务端对集合名做白名单校验，防止越权枚举或检索非预期集合。

6. 跨域（CORS）与网络

  • 浏览器跨域调用：设置 QMD_ALLOWED_ORIGINS=https://调用方域名（多个用逗号分隔）。
  • 服务端互调：无需 CORS；直接 HTTP 调用即可。
  • 本机 localhost 与公网页面之间的 fetch 受浏览器私有网络策略限制，务必保证「页面源」与「请求目标」同源。

7. 部署

# 1) 构建（原生模块需在目标平台编译，勿跨平台复用 node_modules/dist）
npm run build

# 2) 启动服务（默认 8787 端口；对外监听用 0.0.0.0）
node bin/qmd serve --host 0.0.0.0 --port 8787

# 3) 配置 LLM（服务器侧，调用方不传 key）
#    通过网页「设置」面板填写：llmBaseUrl / llmApiKey / llmModel
#    常见厂商基地址：
#      OpenAI      https://api.openai.com/v1
#      DeepSeek    https://api.deepseek.com/v1
#      阿里通义     https://dashscope.aliyuncs.com/compatible-mode/v1
#      智谱 GLM     https://open.bigmodel.cn/api/paas/v4

若修改了源码，必须重新 npm run build 并重启服务，新接口才生效。修改配置（LLM 等）无需重建，前端重发请求即可。

8. 调用示例

8.1 cURL

# 登录拿 token
TOKEN=$(curl -s -X POST http://服务器:8787/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"你的用户","password":"你的密码"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 调用提问接口
curl -s -X POST http://服务器:8787/api/ask \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"如何保守机密？","collections":["ceshi"]}'

8.2 PowerShell（中文用 UTF-8 文件避免乱码）

$tok = (Invoke-RestMethod -Method Post http://localhost:8787/api/auth/login `
  -ContentType "application/json" -Body '{"username":"admin","password":"123"}').token

# 用 .NET 写无 BOM 的 UTF-8 文件，防止中文被终端编码成 ?
[System.IO.File]::WriteAllText("body.json", `
  '{"query":"保守机密的具体要求是什么？","collections":["ceshi"]}', `
  [System.Text.UTF8Encoding]::new($false))

Invoke-RestMethod -Method Post http://localhost:8787/api/ask `
  -Headers @{ Authorization="Bearer $tok"; "Content-Type"="application/json" } `
  -InFile body.json | ConvertTo-Json -Depth 4

8.3 浏览器同页 fetch（相对路径，自动指向当前服务器）

fetch('/api/ask', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer TOKEN' },
  body: JSON.stringify({ query: '保守机密的具体要求是什么？', collections: ['ceshi'] })
}).then(r => r.json()).then(d => console.log(JSON.stringify(d, null, 2)))

9. 安全与运维建议

  • 对外前务必切换为只读查询 Token，切勿共用管理员/全权限 token。
  • 防火墙仅放行调用方 IP；对调用频率做限流与审计。
  • LLM key 仅存于服务器，绝不出现在接口请求或响应中。
  • 监控 error 字段（尤其 fetch failed），用于排查 LLM 出网/地址问题。
  • 建议为不同外部系统颁发不同的查询 token，便于吊销与追溯。
