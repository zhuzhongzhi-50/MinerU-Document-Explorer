添加 Wiki 集合建库流程 · 时序图

本文档说明如何把一个目录作为 type: wiki 集合接入索引（以本次实际执行的 docs-wiki 为例）。Wiki 集合与 raw 集合共用同一套建库管线（文件发现 → markdown 解析 → 智能分块 → 本地 embedding → 向量/FTS5/links 落库），唯一区别是 store_collections.type 标记为 'wiki'，从而在查询期的混合检索中被自动并入。

一、本次实际执行的建库命令

# 1. 删除已占位的 raw 集合（同 path+pattern 冲突，否则 collection add 会拒绝）
npx tsx src/cli/qmd.ts collection remove docs-demo
#   → ✓ Removed collection 'docs-demo'  /  Deleted 7 documents

# 2. 以 wiki 类型从 docs/ 建库（完整跑一遍 indexFiles 管线）
npx tsx src/cli/qmd.ts collection add "E:\wuzhu\Documents\VS Code Gong\MinerU-Document-Explorer\docs" --name docs-wiki --type wiki --mask "**/*.md"
#   → Indexed: 7 new, 0 updated ... ✓ Collection 'docs-wiki' (wiki) created successfully

# 3. 验证
npx tsx src/cli/qmd.ts collection list      # docs-wiki 显示 [wiki] 标签，7 文件
npx tsx src/cli/qmd.ts search "hybrid search architecture" -c docs-wiki --json   # 可检索到 architecture.md

二、建库时序图

说明：虚线为各参与方生命线；实线箭头为调用/返回；索引管线上的 ⑤–⑧ 为其内部子步骤。Embedding 由 src/llm.ts 调用本地 GGUF 模型完成，未单独画泳道以免过宽。

三、逐步骤详解

步命令 / 代码说明关键文件
1qmd collection add <path> --name docs-wiki --type wiki --mask "**/*.md"用户发起建库。CLI 解析 positionals[1]=路径、--name、--type wiki、--mask。src/cli/qmd.ts · parseCLI
2collectionAdd(pwd, glob, "docs-wiki", "wiki")派生集合名；先校验同 path+pattern 是否已存在集合（冲突则报错退出，见本次先 remove docs-demo）。src/cli/qmd.ts
3addCollection(name, pwd, glob, "wiki")在 ~/.config/qmd/index.yml 写入集合，带 type: wiki。src/collections.ts
4resyncConfig() → syncConfigToDb(db, cfg)将 YAML 配置同步进 SQLite store_collections，type 列置 'wiki'。src/cli/shared.ts · src/store.ts
5indexFiles(pwd, glob, "docs-wiki", false, ignore)进入真正建库：fast-glob 按 pattern 发现 7 个 .md 文件。src/cli/qmd.ts
6markdown 后端 parse()逐文件解析标题、正文、内部 wikilink 链接。src/backends/markdown.ts
7chunking.ts 智能分块markdown 感知断点；按 settings：chunkSizeTokens=550，overlap=0.15。src/chunking.ts
8llm.ts embed(chunk)调用本地 GGUF embeddinggemma-300M（已缓存于 ~/.cache/qmd/models）生成向量。src/llm.ts
9store.writeDocument / vec0 / FTS5 / links写 documents、content、向量表（sqlite-vec）、FTS5（BM25）、links 表。src/store.ts
10事务提交返回 docid，索引落盘。src/store.ts
11CLI 打印 ✓ docs-wiki (wiki) created建库完成；collection list 显示 [wiki] 标签。src/cli/qmd.ts

四、配置落点

~/.config/qmd/index.yml（docs-demo 已移除，新增 docs-wiki）：

collections:
  exam:
    path: C:\Users\wuzhu\Desktop\exam
    pattern: "**/*.docx"
    includeByDefault: true
  ceshi:
    path: C:\Users\wuzhu\.cache\qmd\uploads\ceshi
    pattern: "**/*.{md,markdown,txt,pdf,docx,doc,pptx,ppt}"
    type: raw
  docs-wiki:
    path: E:\wuzhu\Documents\VS Code Gong\MinerU-Document-Explorer\docs
    pattern: "**/*.md"
    type: wiki

SQLite store_collections 表：SELECT name, type FROM store_collections WHERE name='docs-wiki'; → docs-wiki | wiki。

关键结论：wiki 集合不需要为 ceshi 重新建索引——ceshi（raw）的向量/FTS 索引原封未动。本次只是新增了一个独立的 docs-wiki（wiki）集合，它走与 raw 完全相同的建库管线，且复用同一 embedding 模型，因此查询期混合检索（raw + wiki）可直接生效，结果按 kind 区分来源。
